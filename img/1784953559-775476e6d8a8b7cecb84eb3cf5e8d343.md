# API网关

简称网关，也是一个服务，作为后端服务的唯一入口，所有的外部客户端访问都需要经过它来进行调度和过滤

![image-20260725085437544](https://cdn.jsdmirror.com/gh/Llodjdkr/typora-images@main/img/1784940879-284b78d613e6ca86cca103e4ee1280bd.png)

核心功能：

1. 权限控制：对用户进行权限校验，校验失败则进行拦截
2. 动态路由：一切请求先经过网关，网关根据规则将请求发到哪个微服务
3. 负载均衡：当路由目标有多个时，进行负载均衡
4. 限流：流量过高时，按照网关配置的微服务最大流量进行放行

# Gateway

## 使用

1. 创建项目并引入依赖

   ```
   <!--网关-->
   <dependency>
   	<groupId>org.springframework.cloud</groupId>
   	<artifactId>spring-cloud-starter-gateway</artifactId>
   </dependency>
   <!--基于nacos实现服务发现依赖-->
   <dependency>
   	<groupId>com.alibaba.cloud</groupId>
   	<artifactId>spring-cloud-starter-alibaba-nacos-	discovery</artifactId>
   </dependency>
   <!--负载均衡-->
   <dependency>
   	<groupId>org.springframework.cloud</groupId>
   	<artifactId>spring-cloud-starter-loadbalancer</artifactId>
   </dependency>
   ```

2. 配置文件，访问接口时通过网关端口进行访问

   ```yml
   server:
     port: 10030
   spring:
     application:
       name: gateway
     cloud:
       nacos:
         discovery:
           server-addr: IP:port #基于nacos实现服务发现
       gateway:
         routes:
           - id:  #路由规则id，随便起
             uri: lb://应用名/ #目标服务地址
             predicates: # 路由条件，满足路由条件，转到目标服务地址
               - Path=/order/** , ...
           - id: 
             uri: lb://应用名/
             predicates:
               - Path=...,...
   ```

## Route Predicate Factories

路由断言工厂，在Gateway中Predicate提供了路由匹配机制。我们在配置文件中写的断言规则会被Route Predicate Factory读取并处理，转为路由判断条件，底层使用Predicate接口进行处理。

### Predicate

Java8提供的一个断言型函数式编程接口，负责接受一个参数并返回一个布尔值，用于条件过滤以及参数的校验

```Java
public class StringPredicate implements Predicate<String> {
    @Override
    public boolean test(String s) {
        return false;
    }
}
Predicate<String> predicate = s-> !s.isEmpty();
.and(Predicate other): 进行与操作,返回一个组成Predicate
.or(Predicate other) :进行或操作,返回一个组成Predicate
.test(T t) :传入一个Predicate参数,用来做判断
.negate() : 将结果取反

```

> 函数式接口：有且仅有一个抽象方向的接口

### Predicate配置项的属性

1. Path，指定url

   ```yaml
   predicates: 
     - Path=/order/** , ...
   ```

2. After/Before，匹配指定日期之后/前的请求

   ```yaml
   predicates: 
     - After=2026-07-25T10:09:43.998449600+08:00[Asia/Shanghai]
   ```

3. Between，匹配两个指定时间之间的请求

   ```java
   predicates: 
     - Between=2026-07-25T10:09:43.998449600+08:00[Asia/Shanghai] , 2026-07-26T10:09:43.998449600+08:00[Asia/Shanghai]
   ```

4. Cookie，请求中包含指定Cookie, 且该 Cookie值符合指定的正则表达式

   ```
   predicates:
     - Cookie=key, 正则表达式
   ```

5. Header，请求中包含指定Header, 且该 Header值符合指定的正则表达式

   ```
   predicates:
     - Header=请求头名称, 正则表达式
   ```

6. Host ，请求必须是某个Host

   ```
   predicates:
     -Host=**.somehost.org,**.anotherhost.org
   ```

7. Method，匹配指定的请求方法

   ```
   predicates:
     - Method=GET,POST
   ```

8. RemoteAddr，匹配指定范围的IP

   ```
   predicates:
     - RemoteAddr=192.168.1.0/24 # /24表示子网掩码255.255.255.0，有效IP为192.168.1.0 ~ 192.168.1.255
   ```

## Gateway Filter Factories

网关过滤器工厂，负责在请求处理前后增加一些逻辑，Filter分为两种类型。Pre类型，路由处理之前执行；Post类型，请求执行完毕，将结果返回给客户端之前执行。根据Gateway的作用范围，将Filter分为GatewayFilter 和GlobalFilter

> GatewayFilter：应用到单个路由或者一个分组的路由上
>
> GlobalFilter：应用到所有路由上，对所有请求都生效

### GatewayFilter

```yaml
spring:
  cloud:
    gateway:
      routes:
          filters:
            - AddRequestParameter=username,en
```

**选项**：

1. AddRequestParameter，为当前请求添加请求参数

   ```
   - AddRequestParameter=参数名, 参数值
   ```

2. AddRequestHeader/AddResponseHeader，为请求/响应添加请求头

   ```
   - AddRequestHeader=请求头名, 值
   ```

3. RemoveRequestHeader/RemoveResponseHeader，从请求或者响应结果中删除某个Header

   ```
   - RemoveRequestHeader=请求头名
   ```

4. RequestRateLimiter，为当前网关的所有请求进行限流过滤，默认采用令牌桶算法实现限流功能

   ```
   filters:
     - name: RequestRateLimiter
     args:
    	 redis-ratelimiter.replenishRate: 令牌填充速度, 即每秒钟允许多少个请求，不会丢弃请求
    	 redis-ratelimiter.burstCapacity: 令牌桶容量, 即每秒用户最大能够执行的请求数量，设置为0表示阻止任何请求
    	 redis-ratelimiter.requestedTokens: 每次请求占用几个令牌, 默认为1
   ```

   > 令牌桶算法原理：
   >
   > 系统以恒定速率向一个桶中放入令牌，每个到来的请求都必须先从桶中拿到令牌之后才能被处理

5. Retry，当后端服务不可用时, 网关会根据配置参数来发起重试请求

   ```
   filters:
     - name: Retry
     args:
   	 retries: 重试次数
   	 statuses: 针对指定状态码进行重试. 对应org.springframework.http.HttpStatus的枚举类
   ```

6. RequestSize，设置允许接收最大请求包的大小，单位为字节，默认5M

   ```
   filters:
     - name: RequestSize
     args:
   	 maxSize: 5000000
   ```

7. DefaultFilters，该配置下的规则对所有路由都生效

   ```
   spring:
     cloud:
   	 gateway:
   	   default-filters:
    		  - AddResponseHeader=
   		  - ...
   ```

### 执行顺序

每一个过滤器都指定一个int类型的order值, 默认值为0, 表示该过滤的优先级. order值越小，优先级越高，执行顺序越靠前

Order值如何指定：

1. Filter通过实现Order接口或者添加@Order注解来指定order值
2. Spring Cloud Gateway提供的Filter由Spring指定. 用户也可以自定义Filter, 由用户指定
3. 当过滤器的order值一样时, 会按照 defaultFilter > GatewayFilter > GlobalFilter的顺序执行

### 自定义过滤器

**实现GatewayFilter**：

继承AbstractGatewayFilterFactory并实现Ordered接口

```java
@Component
//类名统一以GatewayFilterFactory结尾
public class CustomGatewayFilterFactory extends AbstractGatewayFilterFactory<CustomConfig>
        implements Ordered {
    public CustomGatewayFilterFactory() {
        super(CustomConfig.class);
    }
    @Override
    public GatewayFilter apply(CustomConfig config) {
        return new GatewayFilter() {
            /*
            * ServerWebExchange:HTTP请求和响应集合到一起的对象，可以获得请求/响应的信息
            * GatewayFilterChain：过滤器链
            * Mono：
            * Mono.fromRunnable():创建一个包含Runnable元素的数据流
            *  return chain.filter(exchange)执行请求
            * */
            @Override
            public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
                // Pre类型过滤器
                return chain.filter(exchange).then(Mono.fromRunnable(()->{
                    //post类型过滤器
                })); //执行请求
            }
        };
    }
    @Override
    public int getOrder() {
        return Ordered.LOWEST_PRECEDENCE;
    }
}
```

> CustomConfig：自定义的配置类，会自动从args中读取配置并填充
>

**配置**：

```yaml
filters:
  - name: Custom #过滤器名字，默认为CustomGatewayFilterFactory的前缀
  args:
	 name: en
```

**实现GlobalFilter**：

实现GlobalFilter和Ordered接口

```java
@Component
public class CustomGlobalFilter implements GlobalFilter, Ordered {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        //pre逻辑
        return chain.filter(exchange).then(Mono.fromRunnable(()->{
            //post逻辑
        }));
    }
    @Override
    public int getOrder() {
        return Ordered.LOWEST_PRECEDENCE;
    }
}
```
